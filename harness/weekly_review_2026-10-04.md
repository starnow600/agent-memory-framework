### 🚨 异常1：iFinD MCP 连续10个交易日不可用（P1）

**严重程度**：高（核心数据源长时间故障但系统仍在运行）

**现象**：
- 9/24 ~ 10/3 连续10个交易日 iFinD MCP K线返回空
- 健康检查：10次全部失败（available=False, quota_exhausted=False）
- K线获取：12次全部返回空（持仓股 sz300604、sz000938）
- 成功率：33.3%（仅 init 成功，实际数据接口全失败）

**关键发现——"成功的失败"假象**：
- `ifind_data_source_init`（5/5成功）和 `expert_ifind_data_source_init`（6/6成功）均报告"适配器初始化成功"
- 但初始化成功不代表数据接口可用——健康检查和实际K线获取全部失败
- 即**初始化通过是必要不充分条件**，健康检查才是可用性的真实指标
- 当前路由层统计的成功率33.3%高估了实际可用性——如果只看"有真实数据产出"的调用，成功率为0%

**兜底状态**：✅ 三级兜底正常工作

- 但 route_log 中 `fallback_used` 均为 false——兜底在下游风控层执行，非路由层降级
- 与 W12 观察一致：兜底链路埋点不在路由层

**与 W12 对比**：
- W12（9/20-9/27）：MCP"半可用"状态——部分标的可用、部分不可用
- W13（9/27-10/4）：MCP"全不可用"状态——所有K线接口持续返回空，仅init通过

## 五、W13周校准根因修正（2026-10-05补充）

### 🎯 真相：不是MCP挂了，是适配器解析bug

**修正结论**：此前"iFinD MCP连续10交易日全不可用"的判断错误。MCP服务本身完全正常，是 `ifind_mcp_adapter.py` 中的 `_parse_inner_answer` 函数存在解析bug。

**bug详情**：
- 函数期望 `outer["data"]` 是 JSON 字符串，执行 `json.loads(data_str)`
- 但 MCP 插件实际返回的 `data` 已经是 dict 对象
- `json.loads(dict)` 抛出 TypeError → 函数返回 None → 上层认为"MCP返回空"
- init 不走这个解析逻辑，所以 init 成功但数据接口全失败（"成功的失败"假象）

**验证**：
- 直接调用 MCP 工具 `mcp__hexin-ifind-ds-stock-mcp__get_stock_performance`，返回完全正常
- 用 CLI 版本（data-provider 网关）测试，也正常
- 修复解析代码（加 dict 类型判断）后，单元测试通过

**修复时间**：2026-10-04
**验证计划**：10/8 节后首个交易日，确认 MCP 路径恢复正常使用

### 影响修正
