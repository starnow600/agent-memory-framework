# 每日叙事 · 2026-09-29（周二）

## 核心叙事一：专家版影子测试的"不转正"决策——成本收益不匹配的理性选择

### 发生了什么
9/29，风控专家版v2.1.0影子测试在到期后第1天发布了最终评估报告。结论很明确：**不转正，保留为副驾驶模式。** 停止每日并行影子测试，改为"每周日深度复盘 + 异动触发式"的低频模式。

28天影子测试的数据其实不差——止损一致性100%、漏报0次、误报0次、解释完整度达标、纪律检测覆盖4类违规。从技术指标看，几乎所有验收项都达标了。但最终决策是"不转正"，理由有三个：止损判断无增量价值（和主风控完全一致）、主数据源iFinD MCP不稳定（连续5天空数据）、增量价值有限但成本高。

### 为什么
这是一个典型的"技术达标但业务价值不足"的决策。专家版的定位是"知识编码+深度分析"，但28天跑下来发现：
1. **M1止损判断模块的价值为零**——因为它和主风控脚本用的是同一套公式（ATR Hybrid + Chandelier Exit），结果必然一致。编码知识并没有带来新的判断，只是用另一种方式重复了同样的计算。
2. **真正有增量价值的是M6深度分析**——行业基本面、事件驱动、情绪面分析这些"软信息"，但这些内容每天跑的成本（MCP调用、token、执行时间）和其增量价值不匹配。持仓只有2只，每天写深度分析的边际收益递减很快。
3. **iFinD MCP的持续空数据放大了成本问题**——主数据源不稳定意味着深度分析的数据质量打折扣，而专家版不受粗筛保护（固定2只持仓），每次都要走兜底链路，耗时更长。

所以"副驾驶模式"是一个很理性的选择：保留M6深度分析的增量价值，但把调用频率降到"每周一次 + 异动触发"，成本大幅下降，价值密度反而更高。

### 结论是什么
1. **影子测试方法论的又一次验证**：影子测试不是为了"证明自己能行"，而是为了"真实评估增量价值"。这次专家版的"不转正"恰恰说明了影子测试在发挥作用——没有因为投入了开发成本就强行转正，而是用数据说话，成本收益不匹配就降级。
2. **"分析密度"比"分析频率"重要**：对于只有2只持仓的组合，每天做深度分析是过度的。每周一次的深度复盘 + 异动时的快速分析，可能比每天浅尝辄止更有价值。
3. **遗留的问题**：异动触发式逻辑还没实现（依赖主风控日检钩子），iFinD MCP稳定性还在恶化，健康检查告警机制也没建。这些是副驾驶模式能否真正发挥作用的前提。

### 验证节点
- 10/5（周日）：首次周度深度复盘运行，验证副驾驶模式产出质量
- 持续关注：iFinD MCP是否恢复，连续空数据是否触达需要主动介入的阈值
- 待实现：异动触发式深度分析钩子（主风控日检出异动时自动触发专家版）

## 核心叙事二：iFinD MCP连续5天空数据——从"异常"到"新常态"的边界

### 发生了什么
9/29，iFinD MCP健康检查再次失败。这是9/24以来连续第5个交易日的空数据。三级兜底机制确保了风控主流程没有中断——主风控50只全量扫描成功（114.1s），专家版也走腾讯/akshare兜底完成了分析。

但一个值得注意的信号是：连续5天，而且route_log显示9/23那天iFinD MCP还是正常的（kline_fetch全部成功），9/24开始突然全空，之后每天都空。这不是配额耗尽的表现（note里明确写了quota_exhausted=False），更像是接口兼容性或服务端变更导致的突然失效。

### 为什么
这里有两层含义需要分开看：

**第一层：三级兜底架构确实扛住了。** 从9/8 v6.1.2引入三级兜底，到9/24 iFinD MCP开始空数据，中间只有半个月的"安全期"。但兜底机制确实工作了——5天连续主数据源故障，风控一次都没断。这是架构设计的胜利。

**第二层：长期降级运行不是可持续状态。** 如果iFinD MCP一直不恢复，意味着：
- 主风控一直用腾讯/akshare的数据，虽然能算但数据质量可能稍差
- 粗筛模式下iFinD的调用量骤降（kline日均64→2次），反而让问题更不容易暴露
- 深度分析类功能的数据完整性受影响更大

现在的问题是：连续多少天空数据算"需要主动介入"？目前还没有明确的阈值和告警机制——这是体系的一个盲区。

### 结论是什么
1. **"扛住了"不等于"没问题"**。三级兜底保证了业务连续性，但主数据源长期不可用是有代价的（数据质量、深度分析能力、未来新功能依赖）。不能因为兜底成功就忽视根因排查。
2. **需要一个健康检查告警机制**。连续N天失败就主动通知主人，而不是等叙事Review或记忆捕获的时候被动发现。目前这个机制是缺失的。
3. **iFinD MCP的稳定性问题需要跟进**。是插件端的问题还是服务端的问题？有没有修复时间表？这些信息目前都不知道。

## 核心叙事三：持仓小幅企稳——但止损压力还在

### 发生了什么
9/29，两只持仓股在经历了9/28的大跌后小幅企稳：长川科技-0.42%（247.89元），紫光股份+0.22%（31.53元）。大盘HS300继续下探（-3.98% vs MA20），但持仓股的跌幅明显收窄。

浮亏还是-10.53%（-6,284.20元），Hybrid止损继续触发。Chandelier Exit方面，长川还有+1.02%的缓冲，紫光已经跌破CE了（-11.10%）。但按照规则，CE是"最后防线"，HYBRID止损的触发条件是max(ATR,5%固定)更紧，所以主要看HYBRID。

### 为什么
9/28的大跌是普跌（HS300 -2.22%，持仓股跌4-6%），9/29的企稳说明卖压在释放后有所缓解。但企稳不等于反转——趋势分还是0/5，BEAR格局没变，MA20偏离还在扩大。

用户基于"基本面未变的市场情绪杀跌"的判断选择持有，这个判断目前还在有效期内。但需要看到的是，如果继续下跌，这个判断的置信度会持续下降。目前没有明确的"基本面验证失败"的量化退出条件。

### 结论是什么
1. **单日企稳不代表趋势反转**。在BEAR格局下，弱势反弹很常见，止损纪律不能放松。
2. **Chandelier Exit的状态值得关注**。紫光已经跌破CE，这意味着趋势追踪止损也被击穿了。虽然HYBRID止损更早触发，但CE的跌破进一步确认了下跌趋势的强度。
3. **基本面vs情绪面的判断需要时间验证**。如果接下来1-2周持仓股能站稳甚至反弹，说明"情绪杀跌"的判断是对的；如果继续创新低，就需要重新评估。
