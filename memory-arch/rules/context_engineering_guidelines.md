# 上下文工程七件套指南

**版本**: v1.0
**建立日期**: 2026-09-20
**适用范围**: 所有Agent任务（分析类、研究类、代码类）
**核心原则**: 输入精简、输出克制、窗口可控

---

## 为什么需要

上下文不是免费的——token成本随输入长度线性增长，但质量不随长度线性提升。过长的上下文反而会：
- 稀释关键信息，降低模型注意力
- 增加幻觉概率（模型被迫从冗余中"猜"重点）
- 推高成本（尤其重度工具输出场景）

七件套按"从易到难、ROI从高到低"排序。

---

## 七件套清单

### 1. 工具输出前置裁剪（ROI最高）

**做什么**：工具返回结果送模型前，先剥离无关信息。
**适用场景**：搜索结果、网页抓取、API返回、日志输出。

**具体做法**：
- 网页抓取：只保留正文（去导航/广告/页脚/评论），不保留HTML标签
- 搜索结果：只取top-N（默认5条），且每条只留标题+摘要+URL
- API返回：只提取需要的字段，不把整包JSON全塞进去
- 日志/表格：只保留关键行，而非全量

**反模式**：`把这篇文章总结一下 → 先抓全文 → 全量送模型`
**正模式**：`把这篇文章总结一下 → 抓正文 → 提取关键段落 → 送模型`

---

### 2. 上下文窗口裁剪

**做什么**：根据任务需要决定带多少历史上下文，不是越多越好。
**适用场景**：长对话、多轮任务、重复日程。

**具体做法**：
- 事实查询类：不带历史，只带当前query
- 延续讨论类：带最近3-5轮 + 关键结论摘要
- 创作/分析类：带任务目标 + 已产出内容摘要，不带完整对话
- 重复日程类：带上次执行结果摘要 + 本次参数，不带每次的完整记录

**判断标准**：问自己"如果不带这段历史，任务还能完成吗？"——能完成就不带。

---

### 3. 输出长度控制

**做什么**：在system prompt或任务描述中明确输出长度要求，减少模型输出废话。
**适用场景**：所有任务，尤其是批量处理和高频任务。

**具体做法**：
- 分析报告类：明确"300字以内"或"不超过10条要点"
- 状态汇报类：用表格+emoji，减少文字描述
- 代码类：明确"只输出代码，不要解释"或"解释不超过2行"
- 总结类：明确"一句话总结+3个要点"

**检查清单**：输出后自问——删掉一半文字，信息会损失吗？

---

### 4. 检索前过滤（RAG场景）

**做什么**：RAG检索前先做关键词筛选和语义过滤，减少送进上下文的片段数量。
**适用场景**：知识库查询、记忆检索、文档问答。

**具体做法**：
- 关键词命中优先于语义相似度
- 控制top-K（默认3-5条，最多不超过8条）
- 重复/高度相似的片段合并后再送
- 片段过长时先做摘要再送入

---

### 5. Prompt精简

**做什么**：系统提示词和用户指令用最简洁的表达，不堆废话。
**适用场景**：所有任务。

**具体做法**：
- 规则用列表+关键词，不用大段叙述
- 同一规则只说一次，不重复强调
- 格式要求说"输出Markdown表格"，不说"请你以一种清晰的结构化方式用Markdown的表格形式输出"
- 角色设定不写小作文，3句话说清楚身份+风格+边界

---

### 6. 输出格式压缩

**做什么**：用高密度格式替代低密度叙述。
**适用场景**：数据汇报、状态监控、对比分析。

**具体做法**：
- 能用表格不用段落
- 能用emoji标记状态不用文字描述
- 能用数字不用"大幅增加""显著改善"类模糊表述
- 代码输出用紧凑格式，不堆空行

---

### 7. 缓存命中率优化（进阶）

**做什么**：利用模型的prompt caching能力，把稳定不变的内容放在前面。
**适用场景**：高频重复任务、批量处理。

**具体做法**：
- system prompt放在最前且保持稳定（减少cache miss）
- 批量处理时，先列所有任务的共同上下文，再逐个处理
- 相同格式的输出要求放在system prompt里，不重复放在每个query中

## 落地优先级

| 优先级 | 项目 | 预估收益 | 实施成本 | 建议时机 |
|--------|------|---------|---------|---------|
| P0 | 工具输出前置裁剪 | 高 | 低 | 立即做 |
| P0 | 输出长度控制 | 中 | 极低 | 立即做 |
| P1 | 上下文窗口裁剪 | 中 | 低 | 逐步做 |
| P1 | Prompt精简 | 中 | 低 | 逐步做 |
| P2 | 检索前过滤 | 中 | 中 | 需要时做 |
| P2 | 输出格式压缩 | 低 | 低 | 顺手做 |
| P3 | 缓存命中率优化 | 低 | 高 | 不急 |

## 检查清单（S1自检可引用）

每次产出分析/报告类内容前，过一遍：
- [ ] 工具输出有没有冗余信息没删？
- [ ] 带了不需要的历史上下文吗？
- [ ] 输出有废话可以砍掉吗？
- [ ] 能用表格/要点的地方还在写段落吗？

## 自主决策记录

1. **七件套件数选择**：参考业界上下文工程框架（Headroom等），结合主人实际场景（A股量化+记忆架构+探索研究）筛选出7项，砍掉了Agent间内存共享、CCR可逆压缩等不适用的技术
2. **排序依据**：按ROI而非技术先进程度排序，前4项都是"代码改几行就能见效"的
3. **放在rules而非experience**：这是要执行的操作规范，不是避坑经验，所以归到rules体系
