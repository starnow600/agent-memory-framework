## 三、误检率分析

### 3.1 误检统计

| 指标 | 数值 |
|------|------|
| 自检发现的问题总数 | 4个 |
| 真实问题（was_real_issue=true） | 2个 |
| 误检/连锁效应 | 2个 |
| **误检率** | **50%** |

### 3.2 误检分析

2个误检都是**同一个根因的连锁效应**：主风控full模式超时 → 专家版影子测试无基准数据 → 标记为"partial"。

这不是严格意义上的"误检"——下游确实因为上游失败而降质了，只是问题根源不在下游子任务本身。属于**"正确发现了降级但归因为S2问题"**的灰色地带。

**误检率的真实含义**：50%的"问题发现"本质是同一根因的传导效应，不是独立的新问题。改进方向是区分"根子任务失败"和"连锁降级"，避免重复计数。

### 3.3 漏检率分析（更关键的指标）

试点期用户指出了2个错误，但S1/S2自检都没拦住：
- 9/7 PPT 7轮迭代 → S1未覆盖"小修改"场景（后补S1-Lite）
- 9/11 占位版报告转发 → S1未覆盖"日程产物转发"场景（后补S1-Lite扩展）

**漏检率 = 2/(2+4) = 33%**

> 这两个漏检都触发了规则迭代（S1-Lite + 扩展到日程产物），符合"发现→修复"的规则生长逻辑。误检率高但可解释，漏检率更值得关注——漏检意味着质量关卡没拦住问题。

### 4.1 自检耗时

| S2自动补录 | 脚本自动执行，≈0人工耗时 | daily_selfcheck_digest.py自动运行 |

### 4.2 总体开销

- **日均自检耗时**：约1~2分钟（按日均2.8次计算）
- **节省的返工时间**：
  - 9/7 PPT 7轮迭代如果每轮S1-Lite验证 → 至少省4~5轮往返（≈15~20分钟）
  - 9/11 占位版报告如果S1-Lite校验 → 省1轮用户反馈+补跑（≈5分钟）
  - 9/10~9/11 主风控超时被S2及时发现 → 省用户等待时间（≈10分钟）

**ROI判断**：时间开销极小（日均2分钟以内），节省的返工和沟通时间远大于开销。即使按保守估算，投入产出比也在5:1以上。

## 八、决策建议：调整后扩展（调→扩）

### 8.1 决策：调整后扩展，不停滞

**理由**：
1. ✅ **问题减少方向正确**：37.5%的减少率虽然低于回溯预测的42%，但趋势明确。S2子任务验收类问题从3个/月降到0个/2周，效果显著。
2. ⚠️ **S1覆盖范围是瓶颈**：不是S1机制无效，而是触发条件太窄。两次漏检都触发了规则扩围（S1-Lite + 日程产物），说明"发现→扩张"的生长逻辑有效。
3. ✅ **时间开销极低**：ROI>5:1，没有成本压力。
4. ✅ **规则生长机制运转正常**：2周2次迭代，闭环验证了元认知规则的生长能力。
5. ❌ **不停滞**：问题减少37.5%接近30%阈值，停了可惜。但直接扩到4场景风险高——S1的覆盖盲区问题还没完全解决。

### 8.2 调整项（3项）

#### 调整1：S1-Lite工程化写入usage_log
- **现状**：S1-Lite是执行层面纪律，不写入日志，无法量化执行频率和效果
- **调整**：新增S1-Lite写入模式（s1_delivery_check.py支持"lite"scope），30秒验证也记一条
- **目的**：量化S1-Lite执行频率，评估小修改场景的真实覆盖率

#### 调整2：S2区分"根子任务失败"和"连锁降级"
- **现状**：主风控超时导致专家版无基准，专家版也被记为fail/partial，误检率偏高
- **调整**：S2新增"upstream_failed"标记，区分"本任务自身问题"和"上游依赖问题"，不计入独立问题计数
- **目的**：降低误检率噪音，让问题统计更准确反映真实质量

#### 调整3：S2人工验收率提升机制
- **现状**：S2人工验收仅8/21=38%，大部分靠自动补录兜底，验收质量依赖脚本判断
- **调整**：子session返回后主agent必须先调s2_subtask_checkin再回复用户，成为强制卡点（类似S1的硬卡点定位）
- **目的**：提高S2的人工参与度，让验收不只是"脚本发现了明显失败"

### 8.3 扩展项（2个新场景）

调整完成、运行1周验证后，扩展到以下2个新场景：

| 新场景 | 触发时机 | 自检内容 | 来源 |
|--------|----------|----------|------|
| **S3投资决策前自检** | 给出投资建议/信号解读前 | ①止损线是否考虑？②仓位约束是否满足？③信号口径是否正确？ | 回溯验证中"投资类"预防性价值 |
| **S4任务启动前自检** | 派发子任务/启动大任务前 | ①验收标准写了吗？②anchor定了吗？③有没有专用skill？ | 回溯验证中"任务执行类"剩余价值 |
