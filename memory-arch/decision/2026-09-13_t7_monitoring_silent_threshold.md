# T7监控改造 + 静默阈值机制

**日期**：2026-09-13
**类型**：架构变更
**状态**：执行中

---

## 背景

**T7监控问题**：技能系统周报连续4周数据量不足（本周仅7条），核心原因是风控全链路（daily_risk_check、全市场扫描、影子测试）都没有 route_log 记录，且 9/12 iFinD MCP 迁移后 MCP 调用也没纳入监控。这直接影响技能补丁体系的有效性——没有路由数据就没法发现路由失败、工具选错、fallback异常等问题，补丁蒸馏也就断了数据源。

**静默阈值机制**：连续零发现则自动降频。叙事 Review 已验证，可推广到话题追踪等场景。

**触发条件**：架构变更（监控体系改造）+ 用户确认执行。

---

## 决策内容

### T7监控改造方向

从"纯路由计数"升级到"业务目标锚定"：
- 补路由 hook，把风控全链路、MCP 工具调用纳入 route_log 监控
- 监控指标从"调用次数"升级为"业务目标达成率"

### 静默阈值机制

- 新增功能：连续零发现自动降频
- 已在叙事 Review 验证，可推广到话题追踪等场景
- 目的：减少无价值的自动化运行，节省资源
