# 2026-09-08 iFinD配额架构修复决策

**决策日期**：2026-09-08
**决策类型**：架构变更 / 风险修复
**触发背景**：iFinD连续2天（9/7-9/8）日token超限，导致主风控脚本启动阶段超时600s退出，三级兜底的降级逻辑根本没机会运行。这是比9/3双重故障更严重的架构缺陷——数据源故障从"调用级"升级为"启动级"，直接阻塞整个流程。

---

## 一、故障回顾

### 时间线
- 9/7 17:xx 主风控首次因iFinD超限超时失败（首次出现启动级故障）
- 9/7 18:xx 手动fast模式补跑成功（降级路径本身可用，但主脚本走不到）
- 9/8 17:xx 主风控再次因iFinD超限超时失败（连续第二天，触发"连续2天复发需结构性响应"阈值）
- 9/8 17:33 通知主人，安排fast模式补跑 + 派子session修复
- 9/8 18:13 fast补跑完成，数据源自动降级腾讯源，三级兜底生效
- 9/8 19:13 专家版影子测试也完成（iFinD挂了但自身降级逻辑好，成功跑完）
- 9/8 ~17:55 修复任务派发（启动超时熔断 + 配额预警降级）

### 根因分析
1. **启动级阻塞**：脚本在启动阶段获取iFinD token时就失败了，600s超时后直接退出，降级逻辑（iFinD→腾讯→akshare）根本没执行到
2. **9/3 vs 9/8的区别**：
   - 9/3是"调用级故障"——iFinD在fetch_kline调用时超限，能走到降级逻辑
   - 9/8是"启动级故障"——iFinD在初始化token获取时就超限，降级逻辑在token之后，走不到
3. **配额规律**：月初（7月初/9月初）iFinD容易超限，可能与月初风控回测、数据初始化等批量任务集中消耗有关
4. **专家版vs主脚本**：专家版自身降级逻辑完善，iFinD挂了也能跑完；主脚本v6.1.1有启动超时bug

---

## 二、决策内容

### 修复方案：启动超时熔断 + 配额池预警

**1. 启动超时熔断（核心修复）**
- iFinD token获取设置10秒超时（而非默认600秒）
- token获取失败立即跳过iFinD，直接走降级链路（腾讯→akshare）
- 确保主风控至少能产出报告，不因启动级故障全挂

**2. 配额预警降级（主动防御）**
- 检测到iFinD接近日配额上限时，非核心调用（观察池扫描、全市场筛选等）自动降级到次优先级数据源
- 核心调用（持仓止损、大盘Regime）保留iFinD优先
- 保住主风控最关键的两块功能的配额

**3. 版本升级**
- 主风控脚本：v6.1.1 → v6.1.2
- 专家版：v2.0.3（自身降级逻辑已完善，无需改动）
