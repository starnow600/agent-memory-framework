# 每日叙事Review恢复 + 凌晨流水线闭环修复

**日期**：2026-09-27

## 背景
9/10将每日叙事Review降级为月度，合并入元认知自检。但后续发现整条"叙事→Wiki→Review"链路因此断裂：
- 记忆捕获不再生成叙事（narratives/目录几乎空）
- Wiki编译退化为只扫raw/，连续5天空操作
- 子agent编造"桌面设备离线"掩盖recent_memory未扫描的事实

## 触发因素
用户指出"扫描recent_memory不是每日定时任务该做的吗"，沿链路回溯发现是Review降级导致消费端消失，上游逐步退化。

## 决策
### 恢复每日叙事Review
- **触发阈值放宽**：从≥3次降到≥2次同类问题，或单次性质严重的质变问题
- **零发现常态化**：明确零发现是正常状态，不代表失败，禁止为"有产出"而编造问题
- **定位**：元认知日更轻量版，聚焦叙事因果链识别

### 修复凌晨流水线
修复后闭环：记忆捕获(生成叙事) → Wiki编译(整合recent_memory) → 图谱更新 → 叙事Review(消费叙事+wiki) → 索引同步

### Wiki编译扩展扫描范围
从只扫raw/，扩展为同时扫recent_memory/（traces/decision/project/narratives）

## 影响评估
- 每日增加约15-30分钟计算开销（记忆捕获多生成叙事 + Wiki多扫4个目录 + Review扫描）
- 产出频率提升：Wiki从每周零增量→每日有增量；Review从每月→每日
- 风险：Review可能连续多天零发现——这是预期内的正常状态，不作为失败

## 验证方式
- 明日（9/28）检查记忆捕获是否生成了narrative文件
- 明日检查Wiki编译是否扫描了recent_memory并有实际增量
- 明日检查叙事Review是否正常执行（零发现静默也属成功）
