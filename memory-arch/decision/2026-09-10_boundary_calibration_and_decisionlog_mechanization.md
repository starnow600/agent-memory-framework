# 职责边界校准 + Decision Log机制化

**日期**：2026-09-09 → 2026-09-10确认
**类型**：架构变更 + 规则修改

## 背景

9月月度自检报告中，将"用户未执行止损"纳入自我评分并列为P0问题，用户指出这是越界判断。

**用户原话**："决策权在我不应作为你评分扣分的依据，你只要提醒到位，你就做到了你该做的"

## 问题根因

自评体系混淆了"风控监控提醒"和"交易决策执行"的边界：
- 我的职责：监控 → 发现风险 → 提醒 → 提供分析支撑
- 用户职责：交易决策（建仓/止损/加仓等全部投资决策）
- 越界表现：把用户未执行止损当成自己的"失职"来扣分，多次在月度报告/叙事Review中自我批评"纪律违规"

## 决策1：职责边界校准（P0-1）

**行动项**：
1. ✅ 9月月度自检报告已修正（评分80→86，P0问题替换）
2. 清理7/8月月度报告中的越界表述
3. 清理叙事Review（review-log-caveman.md）中的越界表述
4. 清理usage_log中的"纪律违规"类记录（S2中止损相关的fail判定）
5. 写入MEMORY.md规则：明确"投资决策权在用户，我只负责监控提醒和分析支撑"的边界

**验收标准**：所有自评文件中不再出现将用户决策归为自身失职的表述。

## 决策2：Decision Log触发机制化（P0-3）

**问题**：目前decision log靠事后自觉补记，经常遗漏（8月教训未根治）。

**行动项**：
1. 定义触发decision log的明确条件清单（取代模糊的"重大决策"）
2. 在S1交付检查中增加"本次是否产生新决策？是否需要记decision log？"的检查项
3. 建立"决策发生时即建档"的机制，而非事后补记

**触发条件清单（初始版）**：
- 🔒规则增删改
- 架构变更（工具链路、脚本架构、日程架构）
- 风控规则修改
- 新技能安装/卸载
- 重大任务启动/终止（预计≥30分钟的任务）
- 用户明确说"记住/记一下这个决策"

**验收标准**：decision log覆盖率从"靠自觉"提升到S1检查项覆盖，漏记率显著下降。
