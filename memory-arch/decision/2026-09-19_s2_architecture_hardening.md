## 一、问题定性

### 现象
9/18 每日自检 S2=0，预期 5 条，实际 0 条。

### 根因
1. **不存在"日程漂移"**：calendar_get 确认日程从 9/9 重建后始终是纯工单模式（无 script_path），updated_at 未变
2. **纯工单本质是子agent执行**：description 写"主agent执行"没用，CalDAV 工单默认子agent跑
3. **子agent质量不稳定**：9/10-9/11 S2=6条，9/14 S2=3条（漏风控），9/15-9/17 S2=5-6条，9/18 S2=0条
4. **结论**：纯工单模式不可靠，执行质量取决于子agent个体差异，不可预测、不可控、不可复现

### 认知修正
"主agent工单模式"是错误假设。description 不决定执行主体，只决定执行内容。

## 三、S2加固方案

### 架构

```
每日（工作日22:00）→ CodeAct脚本 daily_selfcheck_digest.py
  → sessions_list（优先）
  → 文件系统探测 fallback（FS_PROBE_RULES）
  → S2自动补录 + 去重 + 汇总通知

每周日22:00 → 周校准 weekly_s2_calibration.py（主agent工单）
  → sessions_list 全量对账
  → 补漏 + 校准报告
  → 发现未覆盖子任务，提示补 FS_PROBE_RULES
```

### 设计原则
- **稳定的做高频，不稳定的做低频**：CodeAct 脚本跑日常，主agent做周兜底
- **两层兜底**：sessions_list → 文件探测 → 周校准补漏
- **可验证**：周校准报告量化完整度，透明可追溯

### 验收标准（出口条件）
1. 日常完整度 ≥ 95%（文件探测覆盖的子任务）
2. 周校准漏检率 ≤ 5%
3. 新增子任务 24h 内补探测规则
4. 真实问题率保持 ≤ 5%

**连续 2 周达标**才算通过。

### 时间线

| 阶段 | 内容 | 周期 | 出口 |
|---|---|---|---|
| Phase 3 收尾 | 原计划3项调整 + 问题定性 | 9/15~9/21 | 结案报告 |
| **S2加固期** | CodeAct主体 + 文件探测 + 周校准 | 9/22~10/5 | 连续2周达标 |
| Phase 4 | S3+S4试点 | S2通过后 | 各≥5次实例 |
