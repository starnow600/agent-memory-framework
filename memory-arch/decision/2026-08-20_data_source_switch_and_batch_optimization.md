# 风控数据源切换为iFinD + 批量K线优化决策

**日期**：2026-08-20
**类型**：架构变更 / 重大技术任务 / ≥5分钟大任务
**状态**：已完成并上线运行

---

## 背景

8/20下午风控首次全量扫描失败，暴露两个核心问题：
1. **腾讯API不稳定**：失败率40-100%，下午全面失效，连持仓股K线都拉不到
2. **沙箱600秒超时**：逐只拉取速度慢（4.4秒/只），全量1587只预估200+分钟，根本跑不完

主人先后做了两个决策：
- 选**方案A（换数据源）**：从腾讯API切换到同花顺iFinD
- 选**方案A（多次触发日程）**：工作日17:00起每10分钟触发一次，脚本读进度自动续扫

---

## 决策一：数据源从腾讯API切换为同花顺iFinD

### 触发原因
腾讯K线API当日（8/20）全面失效：
- 失败率40-58% → 下午100%失败
- 连fast模式（持仓+观察池共13只）都跑不过去
- 全市场扫描完全不可用

### 选择方案
主人选择方案A：换数据源为同花顺iFinD API

### 验收标准（7项）
1. ✅ K线拉取从腾讯API切换为同花顺iFinD的 history-quotation
2. ✅ 代码格式转换：sz300604 → 300604.SZ
3. ✅ 返回格式适配：同花顺tables结构 → 脚本预期的数组格式
4. ✅ 评分引擎计算逻辑不变（只换数据源，不改算法）
5. ✅ 断点续扫机制保留
6. ✅ 试跑通过（fast模式+扫描模式100只）
7. ✅ 失败重试保留

### 验收结果
✅ 7项全部通过，18:29完成切换

---

## 决策二：批量K线获取优化

### 触发原因
iFinD逐只模式下速度瓶颈仍在——每只都起一个subprocess，4.4秒/只，全量1587只预估200+分钟，和腾讯时代一样慢。

### 优化方案
发现iFinD的 `history-quotation` 接口原生支持逗号分隔多代码批量查询，一次调用返回所有股票数据。

### 性能验证
| 指标 | 逐只模式 | 批量模式 | 提速 |
|------|----------|----------|------|
| 50只耗时 | 220秒 | **0.916秒** | **240倍** |
| 全量1587只预估 | 200+分钟 | **30-60秒** | 一轮搞定 |

### 验收标准（7项）
1. ✅ 新增批量K线获取函数，一次调用返回N只股票K线
2. ✅ 扫描模式改为批量拉取，单批≤30秒/50只
3. ✅ fast模式、观察池、规避损失计算不受影响
4. ✅ 失败重试、688排除、断点续扫全部保留
5. ✅ 全量1587只一轮扫完预估≤40分钟
6. ✅ 评分结果与逐只模式一致
7. ✅ index.json注册更新

### 验收结果
✅ 7项全部通过，19:36完成改造
**实际全量成绩**：1587只 / 228.8秒（3.8分钟）/ 0失败 / 批量命中率100%
