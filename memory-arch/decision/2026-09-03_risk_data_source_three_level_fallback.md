# 2026-09-03 风控数据源三级兜底架构升级

**决策日期**：2026-09-03
**决策类型**：架构变更 / 风险修复
**触发背景**：9/3主风控因iFinD日token超限+腾讯接口故障双重失败，导致风控完全停摆，被迫手动补算。暴露了两级兜底链的脆弱性。

---

## 一、故障回顾

### 时间线
- 17:22 主风控跑失败：iFinD返回502 `Exceeded the maximum number of token acquisitions for the day`（日token超限）
- 腾讯兜底未生效（后排查为腾讯指数接口当日故障）
- 双重故障导致所有持仓分析失败，风控报告完全出不来
- 19:11 排查确认东财（akshare）接口可用，手动补算持仓数据
- 19:16 出手动补算的风控快报
- 19:23 三级兜底修复完成，S2验收通过

### 根因分析
1. **iFinD超限**：上午专家版深度分析测试多次调用iFinD，耗尽当日token配额
2. **腾讯兜底失效**：腾讯指数接口当日挂掉，个股数据也异常
3. **架构缺陷**：只有两级兜底（iFinD→腾讯），两级同时挂就全挂，缺少第三层保险

---

## 二、决策内容

### 升级前：两级兜底
```
iFinD（主源）→ 腾讯（兜底）→ 失败
```

### 升级后：三级兜底
```
iFinD（主源）→ 腾讯（二级兜底）→ akshare/东财（三级兜底）→ 失败
```

- **第一级**：iFinD（同花顺）—— 主数据源，数据质量最高
- **第二级**：腾讯财经 —— 二级兜底，覆盖大部分场景
- **第三级**：akshare（东方财富/新浪） —— 三级兜底，极端场景下的最后保险

### 修复验证
- 在9/3真实故障场景下（iFinD超限+腾讯挂掉）冒烟测试
- 4只标的（长川科技、紫光股份 + HS300指数等）全部穿透成功
- S2验收通过

---

## 三、决策依据

1. **风控是最高优先级系统**：每日风控不能停摆，数据源可靠性是底线
2. **两级同时故障虽然概率低，但后果致命**：风控报告完全出不来=盲仓
3. **工程冗余是必要的**：三级多源架构是金融数据系统的标准实践
4. **增量修复，风险低**：在现有fetch_kline统一入口后追加第三层，不影响上层逻辑

---

## 四、待跟进事项

1. **iFinD token配额优化**：深度分析模块调用量增加，需要评估是否需要申请更高配额或优化调用策略
2. **幂等保护与数据源一致性**：专家版幂等保护复用旧报告的问题（数据源不同时不能复用）
3. **全市场扫描的降级策略**：主源故障时，全市场扫描是否降级为只跑持仓+观察池
