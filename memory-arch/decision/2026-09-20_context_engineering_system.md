# 2026-09-20 上下文工程七件套规则体系落地

## 决策类型
架构变更 / 规则修改

## 背景
之前上下文优化是零散的（S1只检查关键项、风控数据只取需要字段），没有成体系。每周探索报告后基于Agent安全讨论引出P1-2建议，用户确认落地。

## 决策内容
将上下文工程系统化，输出7项按ROI排序的规则：
1. 工具输出裁剪（最高ROI：搜索/网页结果先精简再送模型）
2. 输出长度控制（分析类任务system prompt加简洁指令）
3. 窗口裁剪（长对话定期压缩摘要）
4. Prompt精简
5. 检索前过滤
6. 格式压缩
7. 缓存优化

## 落地情况
- 规则文件：`memory-arch/rules/context_engineering_guidelines.md`
- 等级：非🔒级长期规则，加入MEMORY.md锚点
- P0两条（工具输出裁剪+输出长度控制）为"立即做"级别

## 依据
用户确认"两件事一起推进"（状态看板+上下文工程）。

## 影响范围
- 话题追踪、每周探索等内容类任务受益最大（大量网页内容冗余度高）
- 成本节省有限（主要成本在iFinD查询次数而非token），但提升输出质量和响应速度

## 验收标准
- 规则文件完整、可执行
- 分析类任务输出更精炼

## 后续行动
观察输出质量变化，必要时补充具体场景规则
