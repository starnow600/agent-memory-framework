# 决策：全域渐进式披露 + MCP Tasks 幂等化 两项目启动

**决策日期**: 2026-10-04（用户确认）/ 2026-10-05（W13周校准正式建档）
**决策者**: 用户确认 + 主agent执行
**决策类型**: 架构

---

## 背景

本周探索（第26周）发现两个架构级方向：
1. **渐进式披露**：Agent Skills / Pi 1.0 的共性架构原则——不常用的工具/技能/数据不预加载，需要时才加载
2. **MCP Tasks**：MCP 928 企业级终版的正式毕业扩展——长任务句柄机制，支持中断恢复

用户对这两个方向感兴趣，确认落地。

---

## 决策内容

### 项目一：全域渐进式披露（W14-W15）

**目标**：将渐进式披露原则应用到所有模块，降低上下文占用，提高执行效率。

**范围**（按优先级排序）：

| 模块 | 现状 | 优化方案 | 优先级 |
|------|------|---------|--------|
| 风控脚本 | 单文件大脚本，全量加载 | 拆分骨架+功能模块，按需import | 🟢 高 |
| 配置管理 | 规则阈值散落在代码中 | 抽独立配置文件，按场景读对应配置段 | 🟢 高 |
| MEMORY记忆 | 锚点全量常驻 | T0常驻/T1精简/T2下沉，三级分级 | 🟢 高（已完成） |
| S2自检 | 每次读完整规则集 | 只加载本次检查命中的规则 | 🟡 中 |
| 记忆图谱 | 全量加载graph.json（2MB） | 查询时按需加载节点和社区 | 🟡 中 |
| Wiki知识 | 编译后页面较大 | 按topic分文件，检索命中才加载全文 | ⚪ 低 |

**验收标准**：
- 风控脚本初始加载token消耗降低≥30%
- MEMORY容量稳定在75%以下（当前68.8%）
- 功能输出与旧版一致（回归测试通过）

### 项目二：MCP Tasks 幂等化前置（W14-W15）

**目标**：为未来 MCP Tasks 协议接入做准备，先实现长任务的可中断、可恢复。

**范围**：

| 任务 | 现状 | 优化方案 | 优先级 |
|------|------|---------|--------|
| 增量扫描（50只） | 同步跑完，不可中断 | 写进度文件，支持断点续跑 | 🟢 高 |
| 历史回测 | 单线程全量跑 | 支持按日期段断点续跑 | 🟡 中 |
| 任务句柄雏形 | 无 | 给长任务分配唯一ID，支持"查进度""取结果" | 🟡 中 |

**不做的事**：
- 不自建MCP服务器
- 不自己实现完整Tasks协议（等平台支持）
- 不做所有任务的幂等化（只做最有价值的长任务）

**验收标准**：
- 增量扫描可在任意点中断，恢复后结果与连续运行一致
- 有任务ID和进度查询机制
- 10/8节后首个交易日即可验证
