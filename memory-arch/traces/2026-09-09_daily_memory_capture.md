## 三、新学习/洞察

1. **启动级故障 vs 调用级故障**：三级兜底设计默认"数据源故障发生在调用时"，但如果故障发生在初始化/启动阶段，降级逻辑根本跑不到。这是架构盲区——所有兜底链的设计都隐含了"程序能启动到降级逻辑"这个前提假设，而这个假设不一定成立。

2. **CodeAct沙箱工具缺失的SDK层异常**：脚本内部做了容错（try-catch多个工具依次尝试），但工具不存在的错误是SDK层抛出的，没进到业务逻辑层的try-catch。等于"内部容错设计再完善，外部环境不支持就全白搭"。修复思路是：SDK调用外层再加一层异常捕获。

3. **S1-Lite首次实战效果**：9/8是S1-Lite规则落地后第一个工作日，4次修改类交付（经费表、风控报告、专家报告、脚本修复）全部做了反向验证，没有出现类似PPT 7轮迭代的返工。一个≤30秒的轻量卡点，拦截效果显著。

4. **iFinD月初超限规律**：7月初、9月初都出现iFinD超限，可能与月初风控回测、数据初始化等批量任务集中消耗有关。如果这是周期性规律，应该在月初前主动降级非核心调用，提前规避。
