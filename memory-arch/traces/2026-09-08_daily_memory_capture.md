## 三、新学习/洞察

1. **交付质量的最小可行卡点**：S1-Lite的灵感来自PPT 7轮迭代——每轮改完都直接发，用户发现问题再打回，来回浪费时间。一个≤30秒的反向验证（"我改的那个地方真的改好了吗？"）就能拦截大部分低级返工。质量卡点不必追求大而全，最小可行卡点+高频执行 > 完美checklist+低频执行。

2. **CodeAct脚本与S1/S2的边界**：S1/S2是"人决策+子agent执行"模式的质量卡点，而CodeAct脚本是"工程化自动化产出"，靠代码逻辑保证质量。把CodeAct塞进S1/S2会陷入"脚本A检查脚本B，谁来检查脚本A"的无限递归。正确解法是影子测试+关键指标对账+月度抽审。

3. **日程调度模式的可靠性差异**：普通description工单模式依赖session理解描述，上下文丢失时就会失败；而CodeAct脚本挂载模式是系统直接执行脚本，可靠性高得多。这是一个隐性的可靠性分层——同是"定时任务"，实现方式不同，故障率差很多。

4. **iFinD超限的连锁效应**：三级数据源兜底设计上是对的，但实际中iFinD超限后逐只回退腾讯/akshare会累计超时，导致整体脚本超时失败。说明"兜底"不只是数据源切换逻辑，还要考虑超时预算分配——第一源耗光时间，后面的源根本没机会跑。
