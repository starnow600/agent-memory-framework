# atom-coze-version-attribution

## Trigger
Coze平台相关异常时：API返回异常/调度失败/路由失效/skill加载异常

## Rule
Coze平台异常时，必须检查Coze版本变更时间线：

### 必查时间窗
- **当前日期前7天**（版本发布到影响滞后期）
- **当前日期前30天**（含历史版本）
- **重大发布日**（如WAIC/年度峰会/产品发布会）

### 检查源
- Coze官方公告（kzfeedback@coze.email 公开回复）
- Coze产品更新日志（如有公开渠道）
- 扣子官方公众号/官网新闻
- 主agent的MEMORY/叙事（历史平台变更记录）

### 关联判断
- 平台发布日 ≥ 故障首次出现日 - 3天 = 强相关
- 平台发布日 ≤ 故障首次出现日 + 3天 = 可能相关
- 平台发布日 < 故障首次出现日 - 3天 = 弱相关

### 报告格式
- 故障首次出现日：YYYY-MM-DD HH:MM
- 疑似平台版本：版本号 + 发布日
- 相关性强度：强/可能/弱 + 依据
- 反馈状态：已发邮件/待发邮件/暂缓

## Why
7/17 WAIC扣子发布3.0版本→7/18-19凌晨流水线Step 1/2连续失败→7/19 review#19 Coze 3.0发布日时间线吻合→强假设"Coze 3.0调度策略变更"。7/22 21:51 P0-024关闭最终判定"平台7/20已修复"=假设验证。**核心洞察**：Coze等核心平台变更必须纳入故障归因时间线——7/17-7/20的"4天平台变更窗口"是流水线故障的强解释变量。

## Source
- 7/17 Coze 3.0发布（WAIC 2026）
- 7/18-19 凌晨流水线Step 1/2连续失败
- 7/19 review#19 Coze 3.0发布日时间线吻合+强假设
- 7/20-21 review#20-#21 假设持续+Coze 3.0证伪失败
- 7/22 21:51 P0-024关闭=平台7/20已修复（最终判定）
- 7/19 7:19 建议反馈kzfeedback@coze.email（用户暂缓）

## 边界
- ✅ 适用：Coze平台API/调度/skill相关异常
- ✅ 适用：扣子相关产品（Coze IDE/Coze空间/Coze编程等）
- ⚠️ 谨慎：第三方skill内部API（不直接走Coze）—— 检查skill本身而非Coze
- ❌ 不适用：纯本地脚本错误（不涉及Coze）

## Anti-pattern
- ❌ 默认假设"自己代码问题"（排除Coze变更前需有证据）
- ❌ 默认假设"Coze问题"（需先穷尽自身问题——7/22 21:52主人纠正）
- ❌ 平台故障归因后不复盘（7/20-22花了3天才确认=教训）
- ❌ 反馈Coze时无证据（应附时间线+log+mtime）
