# atom-financial-code-prefix-whitelist（金融代码前缀必须用白名单而非宽松匹配）

**层级**: Atomic
**ID**: atom-financial-code-prefix-whitelist
**触发**: 编写/修改涉及金融代码（股票代码、指数代码等）判断逻辑的代码时
**来源**: 9/4风控专家版指数判断bug：`startswith("000")`宽松前缀匹配将深市主板000开头个股(如紫光sz000938)误判为指数，导致走指数接口拿错数据，止损判断完全错误

---

## 失败模式

金融代码系统中，**不同类型的代码共用相同的前缀/格式**。用宽松的前缀匹配（startswith、正则通配）来判断代码类型（指数/个股/ETF/转债等），必然会误判——因为你以为的"指数前缀"实际上也被个股在用。

### 典型案例
| 代码前缀 | 你以为 | 实际上 |
|---------|--------|--------|
| 000xxx | 指数（000300沪深300、000001上证指数） | 深市主板个股也用000开头（000938紫光、000002万科、000858五粮液） |
| 399xxx | 深市指数 | 可能也有其他类型用399开头 |
| 510xxx / 159xxx | ETF | 需确认是否与其他品种有重叠 |

### 后果严重程度
🔴 P0级——如果是止损判断用了错误的K线数据，可能导致完全相反的交易决策。9/4专家版最初判断紫光触发止损（实际上是对的，但最初以为是bug），如果方向反了（应该止损但判断成安全），后果致命。

---

## 约束

1. **金融代码类型判断必须用白名单枚举，禁止前缀/通配匹配**
   - 指数：列出所有你用到的指数代码（如沪深300=000300、创业板指=399006等），只有在白名单里的才算指数
   - ETF：同理，白名单枚举
   - 个股：默认类型（不在任何白名单里的 = 个股）

2. **白名单要覆盖实际用到的所有类型**
   - 14个核心指数是风控场景的最小集
   - 如果新增使用其他指数/ETF/转债，必须同步维护白名单

3. **新增代码类型时做交叉验证**
   - 加新指数到白名单前，确认这个代码不会和个股/ETF重号
   - A股代码理论上不会重号（不同板块有分配规则），但跨市场（沪/深/北）有可能性

4. **双脚本/多脚本必须同步修复**
   - 如果有多个脚本都有同样的指数判断逻辑，必须同步修改
   - 9/4就是主风控v6.1和专家版v2.0同步修复

---

## 为什么重要

`startswith("000")` 这种写法在直觉上很合理——"我见过的指数都是000开头的"。但金融代码体系复杂，你没见过的情况很多。宽松匹配在代码量少时没问题，但规模一上来必然踩坑。白名单枚举是唯一安全的方式，代价只是多写几十行代码，收益是避免P0级逻辑错误。

影子测试的价值也在这里体现：这个bug在静态code review中很难发现，只有真跑起来、和基准版对比输出差异，才能定位到。
