# Atomic: 脚本推算必须用户数据校准

## 触发条件
任何脚本/系统推算涉及资金、账户、持仓、cash等关键账户数据时

## 规则
1. **脚本推算值必须明确标注为"推算"**：与"用户实际确认值"在数据源中明确区分
2. **涉及关键账户数据时必须与用户确认**：禁止用推算值直接做决策
3. **已知锚点必须作为参考基线**：用户最近一次确认的账户值是校准基线
4. **偏差超阈值时立即停止使用脚本值**：触发校准流程，询问用户最新实际值
5. **历史推算链的起点本身可能错**：不能从"起点准"假设推到"中间准"

## 数据权威性层级
1. 用户明确确认的当前值（最高权威）
2. 用户明确确认的历史值
3. 用户提供的历史值 + 已知操作记录推算
4. 纯脚本从历史数据推算（最低权威）

## 反面教训
- 7/9 风控脚本从7/1的cash=24,652倒推→41,516，但用户7/8明确确认cash=43,685，差2,169元
- 根因：脚本的历史交易推算链的起点（7/1初始现金）本身就不准
- 7/8-7/9 持续2天使用错误cash值，触发"用户数据>脚本计算"的规则建立

## 配合使用
- 与 MEMORY.md "用户确认数据>脚本计算值" 长期规则配合
- 与 `基础设定/TOOLS.md` 高风险操作Control Policy配合（资金操作属于高风险）
