# plan-monitoring-chain-cross-validation

## 触发条件
多日程覆盖的监控体系需要验证完整性时：T7周报/月度报告/蒸馏日程/任何涉及"多个监控日程是否正常"的判断

## 规则
当系统有多个独立监控日程（如风控检查、前瞻测试、记忆捕获等）时，必须做**全覆盖交叉验证**：
1. 列出所有监控链（每个日程=一条链）
2. 逐链检查最近N天的产出文件存在性（不是只看route_log记录）
   - ⚠️ **必须使用正确的产出路径**：如daily_risk_check产出在`实战投资/每日风控/YYYYMMDD_风控报告.md`，而非`akshare-data/daily_risk_check_YYYYMMDD.md`
3. 标注断档链（最后产出日期 vs 应有产出日期）
4. 评估断档影响：断档期间是否发生了需要该监控覆盖的事件

## 为什么
- 单链检查容易产生"其他链正常"的错觉。8/2发现daily_risk_check中断4天+forward_test断档4天=两条监控链同时存在盲区而此前未被发现
- route_log记录≠实际执行成功：子session可能写了route_log但未产出文件（7/19调查结论）
- 断档影响评估比断档发现更重要：7/29-7/31恰好是兆易跌停打开+深V+利好出货的关键日，风控中断意味着失去了结构化风控判断
