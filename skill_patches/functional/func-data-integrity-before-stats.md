# func-data-integrity-before-stats

## 触发条件
对文件系统数据进行统计分析前（覆盖率计算、执行天数统计、失败率计算等）

## 操作步骤
1. **原始数据完整性验证**（必须先于统计）：
   - `wc -l` 确认行数
   - `ls | wc -l` 确认文件数
   - 检查文件是否被git追踪（`git log -- path`）
2. **数据一致性检查**：
   - 两个数据源交叉验证（如route_log vs trace文件）
   - 标注不一致项（"A有记录但B无文件"）
3. **异常标注**：
   - 发现数据不完整/不一致时，在报告中标注"基于不完整数据"
   - 禁止将异常数据当作结论输出
4. **统计结论**：基于验证后的完整数据计算

## 为什么
- 8/1 T7月度报告基于不完整数据输出了错误结论（"13天无trace"实际9天）
- 子session做统计时倾向于"直接算"而非"先验证"
- 数据不完整≠结论不可用，但必须标注置信度

## 来源
- 8/1 主人质疑T7报告 → 发现统计逻辑问题
- 7/19 同日3条记录调查（route_log写了但文件没产出）
- 与atom-repeat-failure-systemic的关系：≥3次数据不一致=系统性统计问题
