# Functional: AgentKey多源交叉研究流程

## 触发条件
需要多维度数据交叉验证的研究任务：行业研究、竞品分析、热点事件深度调研、投资逻辑验证等，需要搜索+社媒+网页抓取多源交叉

## 功能定位
组合调用 AgentKey 多类工具（搜索+社媒+网页抓取），形成多源交叉验证的研究流程，提高信息可靠性和研究深度。

## 标准流程

### Phase 1: 明确研究问题与范围
- 明确研究目标：回答什么问题？需要什么维度的信息？
- 界定范围：行业/公司/事件？时间范围？地域范围？
- 产出：研究问题清单 + 信息维度框架

### Phase 2: 搜索层验证（2个工具组合）
先用高质量AI搜索获取整体框架，再用通用搜索补充广度。

- **AI深度搜索**：Perplexity 或 Tavily
  - 输入：研究问题的自然语言描述
  - 产出：带引用的结构化回答 + 关键信息源链接
  - 作用：快速建立知识框架，识别关键论点和争议点

- **通用搜索补充**：Brave 或 Serper
  - 输入：从Phase 2.1中识别的关键子问题/关键词
  - 产出：更多来源的搜索结果，交叉验证Perplexity的结论
  - 作用：扩大信息覆盖面，避免单一AI搜索的偏差

### Phase 3: 社媒层验证（按需选择平台）
根据研究主题选择相关社媒平台，获取一线用户反馈和舆情。

- **国内消费/品牌/营销话题**：小红书 + 微博 + 抖音
  - 小红书：用户真实体验、种草/避雷、产品口碑
  - 微博：舆论热度、KOL观点、话题讨论度
  - 抖音：视频内容趋势、用户互动数据

- **科技/行业/专业话题**：知乎 + B站
  - 知乎：专业讨论、深度分析、行业人士观点
  - B站：视频解读、技术教程、UP主评测

- **海外话题**：Twitter + Reddit + YouTube
  - Twitter：实时动态、专家观点、舆论走向
  - Reddit：社区讨论、用户反馈、细分领域深度

- **产出**：社媒舆情倾向、关键观点分布、热度量级、代表性内容
- **判断点**：搜索结论与社媒一线反馈是否一致？有无信息差？

### Phase 4: 网页抓取深度验证
对关键信息源进行全文抓取，验证信息准确性和上下文。

- **工具**：Firecrawl（AgentKey scrape）或 Bright Data（反爬场景）
- **输入**：从Phase 2和Phase 3中筛选的关键链接
- **产出**：网页全文内容，用于深度分析和精确引用
- **筛选原则**：
  - 官方来源/权威媒体优先
  - 数据/事实类关键信息必须抓原文
  - 观点类信息看上下文是否被断章取义

### Phase 5: 交叉验证与综合判断
- 比对不同来源的信息一致性
- 识别矛盾点和信息缺口
- 对矛盾点做进一步针对性查证
- 形成最终研究结论，标注信息置信度

## 依赖的原子补丁
- atom-agentkey-web-search（Phase 2）
- atom-agentkey-social-media（Phase 3）
- AgentKey scrape类工具（Phase 4，按需使用）

## 输出结构
1. 核心结论（一句话摘要）
2. 信息来源分布（搜索/社媒/网页抓取各占比）
3. 关键发现（按主题分组，标注置信度）
4. 交叉验证结果（一致点 + 矛盾点 + 信息缺口）
5. 风险与不确定性提示
6. 参考链接清单（关键信息源）

## 反模式
- ❌ 只靠搜索引擎结果就下结论（缺乏交叉验证）
- ❌ 社媒数据不加筛选全信（有水军/营销号干扰）
- ❌ 信息源全是同一类型（如只看新闻不看用户反馈）
- ❌ 不标注信息置信度（不同来源可靠性差异大）
- ❌ 上来就全平台全量爬取（成本高且效率低）

## 成本控制策略
1. **渐进式深入**：先搜索（低成本）→ 再社媒（中成本）→ 最后网页抓取（按需），每步都判断是否需要继续深入
2. **小样本测试**：社媒平台先用小样本看数据质量和相关性，再决定是否扩大
3. **关键链接才抓取**：网页抓取只抓关键信息源，不要所有链接都抓
4. **优先用免费工具**：简单的先用 web_search/web_fetch，不够再升级到AgentKey

## 适用边界
- 适用：行业研究、竞品分析、热点事件深度调研、投资逻辑多源验证
- 不适用：简单事实查询（web_search足够）、纯数据查询（用对应数据源）、日常信息获取

## 与 deep-research skill 的关系
- **deep-research skill**：完整的研究工作流（入口+调度+报告生成），适合系统性研究项目
- **本功能补丁**：AgentKey多源交叉的具体执行流程，是deep-research可以调用的底层能力之一
- 关系：deep-research 是研究项目的总调度，本补丁是其中"多源数据获取与交叉验证"这一步的具体操作规范
