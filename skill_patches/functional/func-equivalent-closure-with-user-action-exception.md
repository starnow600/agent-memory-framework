# func-equivalent-closure-with-user-action-exception

## Trigger
P0销项判断 / 等价销项评估 / 持仓约束持续实践的状态判定

## Operation
P0销项判断流程（4条件 + 例外处理）：

### Step 1：4条件check
1. **regime条件**：当前regime是否仍为P0设定的目标regime？
   - 例：P0-014目标=regime切换→若仍BEAR=不满足
2. **HS300趋势条件**：HS300是否站上目标均线（MA20/MA60）？
   - 例：P0-014目标=HS300>MA20→若仍-1.51%差距=不满足
3. **信号质量条件**：chase T+3/reversal T+5等核心指标是否达标？
   - 例：P0-014目标=chase T+3≥48%→若39.9%🔴=不满足
4. **持仓约束条件**：单只≤30%/试探仓≤15%是否满足？
   - 例：若已建仓=部分满足（1只持仓=超约束）

### Step 2：实质销项 vs 例外处理
- **全满足** = 实质销项（"动作+无需操作+主人接受"）
- **全不满足** = 继续维持（原P0延期+继续观察）
- **部分满足 + 1条件"用户主动"** = **等价销项（例外）**
  - 例外条款：用户主动建仓/用户主动调权/用户主动叫停
  - 处理：标记"已发生事实不构成批评"，进入持仓线单独管理
- **部分满足 + 无用户主动** = 继续观察（下次复检）

### Step 3：销项记录
- 写入p0_tracker表（Type A/B/C分类）
- 更新MEMORY.md对应章节（如有P0编号变化）
- 累计销项次数+1，等价销项单列计数

## Why
7/22 P0-014第10次等价销项：4条件全不满足+用户主动建仓兆易=实质销项（"已发生事实不构成批评"）。7/25 P0-014第11次：4条件部分满足+持仓超30%约束+用户主动=不激活=等价销项。**核心洞察**：P0销项不是机械的"deadline到期=违规"，而是"实质条件+用户意图"的联合判断。"用户主动"是P0销项的合法例外条款。

## Source
- 7/22 P0-014第10次等价销项（4条件全不满足+用户主动建仓兆易）
- 7/25 P0-014第11次（4条件部分满足+持仓超30%+用户主动=不激活）
- 7/12 P0-013实质完成（"监控了但无需操作"等价销项首例）
- 7/15 P0-020≠等价销项（用户主动叫停≠"无需操作"——是边界）
- MEMORY 🔒规则"等价销项=动作+无需操作+主人接受=实质完成+例外（叫停不适用）"

## 边界
- ✅ 适用：P0的"持续观察类"P0（如P0-014维持空仓观察）
- ✅ 适用：P0的"窗口期决策类"P0（如P0-015/P0-024）
- ⚠️ 谨慎：P0的"必须执行类"P0（如P0-001紧急修复）—— 等价销项不适用
- ❌ 不适用：P0的"已叫停/已废弃"——应走废弃流程

## Anti-pattern
- ❌ 机械执行"deadline到期=违规"（忽略"用户主动"例外）
- ❌ 把"叫停"误判为"等价销项"（7/15 P0-020的边界教训）
- ❌ 部分满足但未标注"用户主动"维度（漏掉例外条款）
- ❌ 等价销项后不更新p0_tracker表（数据不一致）
- ❌ 等价销项>3次后不规则化（错过机制升级机会）
