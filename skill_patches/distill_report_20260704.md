## 二、本周成功轨迹 → Planning/Functional 提取

### 2.1 新增 Planning ×1

#### plan-failure-notify（任务失败必须通知）
- **来源**：7/3 Step5静默失败 + 叙事 `2026-07-03_任务失败必须通知.md`
- **触发**：任何子任务/子session/定时任务执行失败或异常时
- **模式**：
  1. 立即通知主人（任务名+原因+建议）
  2. 禁止代判重要性
  3. 等主人决定
- **叙事帮助发现的深层模式**：
  - memory_search只能找到"7/3 Step5失败了"这个事实
  - 叙事揭示了**根因**：我替主人做了"这事不重要"的判断，剥夺了知情权
  - 这个模式具有泛化价值：任何"agent代判重要性"的场景都可能触发同类问题

### 2.2 新增 Functional ×1

#### func-narrative-in-distill（执行场景Wiki知识主动读取）
- **来源**：7/3 Wiki/Skill边界讨论 + 叙事消费洞察
- **触发**：执行蒸馏/追踪分析/任务规划/工具选择等需要历史因果链的场景
- **模式**：
  1. 识别知识需求（当前任务是否需要因果链知识）
  2. 主动读取Wiki获取完整因果链
  3. 与叙事交叉验证
  4. Wiki不做路由决策
- **叙事帮助发现的深层模式**：
  - 叙事 `2026-07-03_wiki_skill_boundary.md` 揭示了Wiki消费率≈0%的真正原因
  - 没有叙事，我只能匹配"有Wiki这个工具"的事实碎片
  - 有了叙事，我理解了"Wiki消费率0%=失去了主动找活的能力"这个因果关系
  - 直接催生了"Wiki三层消费模型"（被动→主动→元层），这是memory_search碎片匹配无法发现的

## 三、本周失败轨迹 → Atomic 补充

### 3.1 新增 Atomic ×2

#### atom-why-two-modes（why字段的双重作用模式）
- **来源**：7/4 agent_recipe回测报告"发现2"
- **触发**：编写规则/patch/skill的why字段时
- **规则**：
  - 高频违反的规则→why侧重"元认知打断"（"这正是规则要防止的陷阱"）
  - 子session/无上下文的执行者→why侧重"原理传递"（"因为子session没有X，所以需要Y"）
- **叙事帮助发现的深层模式**：
  - 回测报告中9个事件的对比分析揭示了why字段的两种不同作用机制
  - 这个区分不是来自memory_search（搜索"why字段"只能找到规则文本本身）
  - 是通过回测叙事中的事件对比才发现的：事件#1（路由遗漏）和事件#3（数据源混淆）的why写法应该有本质区别

#### atom-repeat-failure-systemic（重复失败=系统性问题信号）
- **来源**：7/4 agent_recipe回测报告"发现1" + 风控遗漏全量扫描×3
- **触发**：同一规则/约束被违反≥3次时
- **规则**：
  - 3次重复 = 系统性问题，不是偶然
  - 必须引入completion criteria checklist
  - 优先级最高改进项
  - 降级必须标 `[PARTIAL: xxx]`
- **叙事帮助发现的深层模式**：
  - 叙事 `2026-07-03_任务失败必须通知.md` 和回测报告共同指向：风控遗漏3次重复不是执行力问题，是流程设计缺陷
  - "没有completion criteria→部分完成被当成全部完成"是一个系统性认知偏差
  - 这个模式可迁移到所有"多步骤执行"场景

## 六、叙事增值分析（本次新增项）

### 6.1 叙事帮助发现了哪些memory_search找不到的模式？

| 模式 | memory_search能找到的 | 叙事额外发现的 |
|------|---------------------|---------------|
| plan-failure-notify | "7/3 Step5失败" | **根因**：代判重要性→剥夺知情权。泛化到所有"agent代判"场景 |
| func-narrative-in-distill | "Wiki消费率≈0%" | **因果**：不是工具不好用，而是"失去了主动找活的能力"→Wiki三层消费模型 |
| atom-why-two-modes | "agent_recipe回测通过" | **机制区分**：why字段对agent自身vs子session有完全不同的作用方式 |
| atom-repeat-failure-systemic | "风控遗漏3次" | **系统性诊断**：3次=流程设计缺陷而非执行力问题→completion criteria是最高杠杆改进 |

**核心结论**：叙事的价值在于提供**因果链**和**泛化路径**。memory_search能找到"发生了什么"，但叙事能回答"为什么发生"和"这个模式还能用在哪里"。这是v0.4叙事增强的核心价值。

### 6.2 图谱narrative字段的辅助作用
- 通过EVOLVED_FROM关系的narrative，发现三条演化链（量化引擎/统一索引/知识图谱）都指向"从功能堆叠到因果串联"的元模式
- 通过CAUSED_BY关系的narrative，确认工业富联→ATR止损的因果链完整且可溯源
- 通过COMPLEMENTED_BY关系的narrative，确认长川科技和工业富联作为两个止损验证案例的互补关系

## 十一、本周蒸馏亮点

### 11.1 v0.4叙事增强的首次实践价值
本次蒸馏首次完整执行了"叙事→Wiki→图谱→蒸馏"的Loop Engineering链路。核心收获：
- **叙事不是流水账**：每篇叙事都有"发生了什么→为什么→学到什么→和什么相关"的完整因果链

- **图谱narrative字段是浓缩版叙事**：关系的narrative字段能在不读全文的情况下快速理解概念间的因果关系
